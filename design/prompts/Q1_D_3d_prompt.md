## 任务

Q1 候选版本 D（`design/q1/variants/d-paths/`）的图 1a 是连接散点图，一张图里有三个变量：横轴 ODSP 案件数，纵轴 OW 案件数，时间沿着路径走。小组想试试把它做成 **3D 立体**：三个变量各占一条轴。

你的任务是做出这个 3D 视图，同时**保证它不违反课程原则、不降低可读性**。最终要能在网站上呈现，并尽量满足老师的满分要求。

**先读这些**：`design/q1/Q1_DESIGN.md`（尤其是 D 一节和自检）、`design/q1/README.md`、`design/q1/variants/d-paths/`（`index.html`、`d.js`）、`design/q1/shared/`、`design/DESIGN_LOG.md`（包括版本规则），以及附件。

## 必须先知道的风险

课程（Munzner，L3）对 3D 的态度是“没有充分理由就不用 3D”（No unjustified 3D）。现有的 Q1 自检里，3D 也被列为常见错误。3D 的主要问题包括：
- 深度方向的位置几乎无法准确判断，是排名很低的通道；
- 点和线会互相遮挡；
- 透视会让长度和斜率变形；
- 用户必须旋转才能看清，交互成本高；
- 斜着看时文字难读，静态截图（交给老师的 `report.pdf`）也很难读。

所以 3D **不能只是为了好看**。下面的设计就是为了给它一个站得住的理由。

## 设计方案：3D 时空路径，由三个 2D 投影串起来

**核心想法**：把三个变量放进一个立方体：X = ODSP，Y（向上）= OW，Z（纵深）= 时间（2003Q1 → 2026Q1），93 个季度连成一条空间曲线。沿三个轴的方向正视这个立方体，刚好得到三张熟悉的 2D 图：
- 沿时间轴看：**OW 对 ODSP 的连接散点图**，也就是现在的图 1a；
- 沿 ODSP 轴看：**OW 随时间变化**；
- 沿 OW 轴看：**ODSP 随时间变化**。

所以这里 3D 的作用是把这三张 2D 图连起来，让用户看清它们是同一份数据的三个侧面。**读数值一律在 2D 正视状态下进行。** 这对应 L7 讲过的 space-time cube（时空立方体），以及 Bach et al. (2014) 对时空立方体操作的总结：把立方体压平（flattening）成 2D 投影，就是这里的三个视角。请核实这篇文献的出处和链接，写进 `REFERENCES.md`；如果找不到，就不要引用。

### 具体要求
1. **默认是 2D。** 页面打开时图 1a 仍然显示现在的 2D 连接散点图。这样页面不交互也完整，静态截图也能读。3D 通过一个视图切换进入，例如分段按钮 `Path (OW vs ODSP) | 3D | OW over time | ODSP over time`。也可以加一个叙事步骤，在这一步自动转到 3D 再转回来。
2. **正交投影，不用透视。** 平行线保持平行，同一方向上的长度可以比较。
3. **视角预设与动画。** 三个正视视角，加一个斜视 3D 视角。切换时摄像机平滑旋转约 600–800ms；`prefers-reduced-motion` 时直接切换，不做动画。转到正视角时，坐标轴、刻度和标签要变成和对应 2D 图完全一样的样子（同样的刻度、标签和网格），用户能感觉到“它转成了一张普通的图”。
4. **斜视时帮助判断深度**：
   - 在三面“墙”（底面和两个侧面）上用很淡的线画出路径的投影（shadow projection）；
   - 当前季度（滑块位置或悬停的点）画出到三面墙的垂直引线（drop lines），读数显示在旁边的读数面板里；
   - 坐标轴和刻度标签始终正对屏幕（billboard），不随旋转倾斜变形。
5. **自由旋转是辅助功能**：鼠标拖动或手指拖动旋转，键盘方向键旋转，双击或“Reset”按钮回到斜视预设。旋转角度要有范围限制，避免把图转到上下颠倒。
6. **沿用 D 现有的编码和联动**：
   - 两条轴用同样的“每个指数点”比例（2019Q4 = 100），45° 等速增长参考线在 3D 中对应一个参考面或参考线，要说明它的含义；
   - 疫情前、中、后三段用现有的有序中性色阶（浅 → 深）；
   - 时间滑块、Play 按钮、悬停读数、和图 1b/1c 的联动竖线全部继续可用，3D 中的当前点和滑块同步；
   - “Axes in cases / Axes as index” 切换在 3D 中也有效。
7. **技术**：优先用 D3 + SVG 自己写正交投影（93 个点、几条坐标轴和网格，计算量很小）。这样可以沿用现有的 CSS 变量、深浅主题和文字样式，也不需要 WebGL。如果你判断必须用 three.js，先说明理由；库要从 cdnjs 按固定版本加载。
8. **手机**：400px 宽度下 3D 仍然能用（触摸拖动旋转、预设按钮），页面不需要横向滚动。如果手机上 3D 实在读不清，可以在手机上默认隐藏 3D 按钮，并写明原因。
9. **可访问性**：所有按钮可以用键盘操作；3D 区域有 `aria-label`，说明可以用方向键旋转；读数面板保持 `aria-live`。

### 不要做的事
- 不要用透视投影、3D 柱状图、3D 曲面，也不要用阴影或光照特效。
- 不要让 3D 成为读取数值的唯一途径。
- 不要改动 A、B、C 三个版本，也不要改 Q3。

## 设计说明里要写清楚的内容（中英双语）
在 `Q1_DESIGN.md` 的 D 一节新增“3D 时空路径”小节，包括：
- **为什么用 3D**：三个变量，一个是时间；三个正视投影正好对应三张 2D 图；3D 是连接它们的过渡，不是读数用的。对应 L3（effectiveness：读数在共同尺度的位置上进行）、L5（change mapping、navigation、linked views）、L7（space-time cube 的 flattening 操作）。
- **代价和应对**：遮挡、深度难判断、交互成本、静态图难读，分别用墙面投影、引线、正交投影、默认 2D 和预设视角来应对。
- **考虑过但放弃的方案**：透视 3D、只能自由旋转（没有预设）、Plotly 等现成 3D 库（体积大，风格和主题难统一）、直接用 3D 替代 2D。
- **Motivation / Appeal / 代价**这三项更新到 D 的简介和总览页 `design/q1/index.html` 的卡片里。
- **对报告的影响**：mock design 的 `report.pdf` 是静态的。说明报告里用哪几张图（建议一张斜视 3D 加三个正视投影的小图组），以及它们放得下放不下。
