## 七条规则 / Seven Working Rules

1. **沟通 / Communication.** 日常使用微信群，复杂或紧急事项通过 Zoom 讨论，具体响应时限待核对。<br>Use WeChat for daily communication and Zoom for complex or urgent discussions. Specific response times remain to be confirmed.
2. **会议 / Meetings.** 使用 Zoom，频率按项目进度安排；缺席或时间变化尽量提前一天告知。会后一天内查看纪要并确认任务。<br>Meet on Zoom as project progress requires. Where possible, give one day's notice of absence or availability changes. Read the minutes and confirm action items within one day after each meeting.
3. **进度 / Progress.** 负责人每两至三天更新一次，上传材料后通知群内成员，说明已完成工作、困难和下一步。<br>Leads update progress every two to three days. After uploading materials, notify the group and explain completed work, difficulties, and next steps.
4. **任务与复核 / Tasks and Review.** 负责人统筹，支持成员共同完成和检查；在 GitHub 拆分子任务并保留成果链接，原则上提前两天准备组内审阅版本。<br>Leads coordinate; supporting members help complete and review tasks. Track subtasks and output links on GitHub. In principle, prepare group review copies two days before official deadlines.
5. **版本管理 / Version Management.** 文书与代码分库存放；归档文件按 `任务名_YYYY-MM-DD_vN.ext` 命名，正式提交文件保留课程规定名称。负责人和支持成员共同核对更新及最终版本。<br>Keep documentation and code in separate repositories. Name archived versions `task_YYYY-MM-DD_vN.ext`, while retaining required filenames for official submissions. Leads and supporting members check updates and final versions together.
6. **延期与困难 / Delays and Difficulties.** 预计无法按时完成时尽快在群内说明，协商恢复计划、支援或重新分工；进一步升级流程待确定。<br>Notify the group promptly if a deadline is at risk. Agree on a recovery plan, support, or reassignment. Further escalation procedures remain to be determined.
7. **贡献与修改 / Contributions and Changes.** 记录实际工作和估计工时，每次会议复核进度、工作量和里程碑。协议修改由全组讨论同意，并同步全体成员。<br>Record actual work and estimated time. Review progress, workload, and milestones at every meeting. Changes to this agreement require group discussion and agreement, followed by notification to all members.
